# 执行流程（衍生版新增）

## W1 事实与任务

建立当事人表、事件时间线、材料目录和 facts。记录题目原文、资料页码/段落、请求方向与救济目标。区分 stated（材料记载）、disputed（有争议）、unknown（未提供）；用原文中的表述保留否定事实，不凭沉默推定否定。法律评价写到后续 issues，不污染事实记录。

识别决定性缺口，例如通知到达时间、履行情况、权利归属。可以使用条件分支继续；不得自行补全。真实诉讼分析与给定事实的课堂案例分开：前者记录证据争议与举证问题，后者遵守题目明确给定的事实。

## W2 找法与大纲

按当事人方向和救济目标发现合同、类似合同、物权、侵权、无因管理、不当得利等候选。检索顺序仅供发现，不意味着排斥其他请求权；不得把“不当得利兜底”作为自动排除理由。

每项候选记下支持线索、可能反对因素、规范功能（请求权基础/辅助规则/形成权/防御规则）、选入或排除理由及来源。形成权的享有、行使及其后果分别处理，不把解除或撤销直接称作给付请求权。

先获取原文及历史版本，再核对案件时间、主体、地域与过渡规则。检索未命中记入 retrievals，不等于规范或请求权不存在。遇到新材料允许重开候选清单，登记受影响的 claim/issue ID。

按产生、未消灭、可行使展开给付请求权；区分成立要件、效力障碍、消灭事由、行使抗辩。按具体制度调整结构，防止机械套表。保留请求权竞合、主备位关系、同一损害避免重复受偿、金额范围及期限问题。否认、抗辩及举证责任分别核对其依据。

## W3 论证

按 reasoning.md 逐 issue 建立来源→法律命题→事实对应→反向因素→结论。结论类型为 supported、not_supported、conditional、unresolved；后两者须给出条件或缺口。

确定前提不成立时，后续可标不必检视并说明依赖关系；前提有争议时可在明确假设下作备位分析，不得把条件结论写成确定事实。数额计算列出输入、单位、期间和算式，核对各请求权是否重复覆盖。

## W4 审查与修订

先审实质，再审可读性：

1. 来源是否实际读取，命题是否受具体段落支持，历史版本是否适用。
2. 事实是否忠实，未知是否被当成不存在，举证责任是否被随意倒置。
3. 候选是否遗漏，反对依据是否回应，竞合及金额是否一致。
4. 引用可定位、术语一致、格式可读。排版错误不与虚构来源等量处理。

修订时跟踪受影响的来源、命题、下游 issue 和结论，重新核对整个依赖范围，而非只核对改动文字。最多进行三轮定向修订以避免空转；仍有关键缺口则标 provisional 并列明问题，不强行通过。用户微调若改变法律含义，同样触发复核。

运行结构检查后，实质复核结果写入 review。只有结构检查通过且关键问题全部解决，才能标 reviewed。无工具不伪造通过记录。输出 Markdown；用户要求且工具可用时导出文档，再检查文档标题、脚注、中文与表格。输出后不得自动发布案件内容。
